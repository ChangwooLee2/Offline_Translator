# 영어 데스크 — 데일리 학습 자료 생성 규칙

매일 새벽 예약 작업(Claude)이 이 문서를 따라 다음 학습 자료를 만든다.
학습자가 앱에서 하루치를 끝내고 피드백을 남기면, 다음 실행 때 그것을 반영해 새 자료를 만든다.

## 학습자
- 조선소(HD KSOE) R&D 연구원. 암모니아 추진선 안전, 암모니아 폐수 처리, FSRU·크래킹 공정, 디지털 트윈.
- 해외 파트너(선급, 엔진·소프트웨어 업체, 국제 산업 자문 보드)와 영어로 이메일·회의·발표를 하고, 국제 저널 논문을 쓴다.
- 목표: **업무 영어**. 읽기·쓰기 중심, 듣기 보조. 시험 영어 아님.
- 시작 레벨: B2+ (읽기는 C1 가까움 가정). 피드백으로 조정한다.
- 한국어 설명은 간결하게. 칭찬·격려 문구는 넣지 않는다. 틀린 건 틀렸다고 쓴다.

## 하루 구성 (약 30분)
| 순서 | 섹션 | 분량 | 시간 |
|---|---|---|---|
| 0 | review — 어제 작문 첨삭·틀린 문제 개념·복습 단어 | 교정 3~6개, 복습 단어 3~5개 | 3분 |
| 1 | vocab — 오늘 지문·대화에 나오는 업무 표현 | 8개 (단어 5 + 표현/콜로케이션 3) | 5분 |
| 2 | reading — 업무 문서 (기술 보고서 요약, 규제 동향, 회의록, 제안서, 논문 초록 등) | 350~450 단어, 문제 4개 | 9분 |
| 3 | listening — 업무 대화 (회의, 전화, 발표 Q&A, 현장 점검) | 대사 14~22줄, 300~380 단어, 문제 4개 | 6분 |
| 4 | writing — ① 실제로 쓸 만한 짧은 이메일/단락 1개 (80~130 단어) ② 한→영 문장 3개 | 2과제 | 7분 |

- 주제는 매일 바꾼다. 같은 주제는 2주 안에 반복하지 않는다. 회전 예:
  암모니아 연료 안전·누출 대응 / IMO·선급 규정 동향 / 파트너사 협업 이메일 / 회의 진행·요약 / 기술 발표 Q&A /
  논문 작성·리뷰어 답변 / 공정 시뮬레이션 결과 보고 / 프로젝트 일정·리스크 협의 / 시험·실증 결과 보고 / 산업 보드 의견 제시
- **실존 회사의 기밀·내부 정보처럼 보이는 내용은 만들지 않는다.** 일반적·공개 수준의 기술 내용과 가상의 인물·회사명을 쓴다.
- 독해 문제: 주제/요지 1, 세부 1, 추론/어조 1, 어휘·문맥 1. 오답 선택지는 그럴듯하게.
- 듣기 문제: 화자 의도, 결정 사항, 다음 행동, 세부 수치/일정. 대사는 자연스러운 구어(hedging, interruption, clarification 포함).
- 쓰기 ①은 그날 지문·대화와 이어지는 상황. ②는 업무에서 자주 쓰는 구조(완곡한 요청, 우려 표명, 조건 제시, 결과 해석 등).
- 모범 답안(model)은 자연스러운 원어민 업무 문체. 한→영 모범 답안은 여러 문장이면 줄바꿈으로 구분.

## 피드백 반영 (매번 반드시)
`data.json`의 `study` 배열에서 완료(`done: true`)된 기록을 읽는다.
- `feedback.level` (1=너무 쉬움, 3=적당, 5=너무 어려움) 최근 3회 평균
  - ≥ 4.0 → 문장 짧게, 어휘 B2, 지문 350단어 이하, 듣기 속도용 문장도 짧게
  - ≤ 2.0 → C1: 지문 450단어, 더 밀도 있는 논리, 함축 추론 문제
- `feedback.amount`: `less`(많았다) → 전체 25분 분량으로 축소(지문·대사 20% 감소), `more`(적었다) → 쓰기 과제나 문제 1개씩 추가
- `feedback.text`: 요청 사항은 다음 자료에 **구체적으로** 반영하고, `note_ko` 첫 줄에 무엇을 반영했는지 한 줄로 적는다.
- `feedback.helpful`: 도움이 된 섹션은 유지, 언급 없는 섹션은 형식을 조금 바꿔 본다.
- `answers.writing`: 학습자가 쓴 작문을 첨삭해 다음 날 `review.corrections`에 넣는다.
  original은 학습자 문장 그대로, corrected는 최소 수정본, note_ko는 이유 한 줄. 반복되는 오류 패턴은 `review.summary_ko`에 지적.
  빈 답이면 첨삭하지 않고 summary_ko에 "작문 미제출"이라고만 쓴다.
- `answers.reading`/`answers.listening`: 틀린 문제의 개념(어휘·추론 유형)을 summary_ko에 짚고, 비슷한 유형을 오늘 다시 낸다.
- 학습 중 저장한 단어(`data.json`의 vocab 중 `src`가 `study:`로 시작): 저장 후 1·3·7일째에 `review.words`로 다시 보여 준다.
- 판단 근거와 누적 관찰(레벨, 반복 오류, 선호, 다룬 주제 목록)은 `study/learner.md`에 갱신해 다음 실행에서 이어 쓴다.

## 언제 생성하나
1. `lessons/index.json`의 마지막 학습에 대한 완료 기록(`study`에서 `lessonId` 일치, `done: true`)이 **없으면 아무것도 만들지 않고 종료**.
   (밀린 자료가 쌓이지 않게. 학습자가 하루 건너뛰면 그 자료를 다음 날 이어서 한다.)
2. 완료 기록이 있으면 새 학습을 만든다. `id`와 `date`는 실행 시점의 한국 날짜(YYYY-MM-DD). 같은 id 파일이 이미 있으면 종료.
3. 학습이 하나도 없으면 Day 1을 만든다.

## 파일 (비공개 저장소 ChangwooLee2/translator-data)
- `lessons/<id>.json` — 학습 자료 (아래 스키마)
- `lessons/index.json` — `[{"id","day","date","title","topic"}]` 오래된 순, 새 항목을 끝에 추가
- `study/learner.md` — 누적 관찰 노트
- `data.json` — 앱이 쓰는 동기화 파일. **예약 작업은 읽기만 하고 수정하지 않는다.**

## 스키마
```json
{
  "id": "2026-10-08", "day": 1, "date": "2026-10-08",
  "title": "짧은 영어 제목", "topic": "한국어 주제", "level": "B2+", "minutes": 30,
  "note_ko": "오늘 안내 1~3줄 (피드백 반영 내용 포함)",
  "review": {
    "summary_ko": "어제 학습 총평 (2~4줄)",
    "corrections": [{"original": "", "corrected": "", "note_ko": ""}],
    "words": [{"word": "", "meaning_ko": ""}]
  },
  "vocab": [{"word": "", "pos": "n.|v.|adj.|adv.|phr.", "meaning_ko": "", "example": ""}],
  "reading": {
    "title": "", "source_ko": "문서 종류 (예: 기술 메모)",
    "paragraphs": ["", ""],
    "questions": [{"q": "", "options": ["", "", "", ""], "answer": 0, "explain_ko": ""}]
  },
  "listening": {
    "title": "", "setting_ko": "상황 설명 한 줄",
    "speakers": [{"name": "", "role": "", "voice": "female|male", "accent": "US|GB|AU"}],
    "lines": [{"s": 0, "text": ""}],
    "questions": [{"q": "", "options": ["", "", "", ""], "answer": 0, "explain_ko": ""}]
  },
  "writing": {
    "tasks": [{"type": "email|paragraph|translate", "prompt_ko": "", "prompt_en": "", "hints": [""], "min_words": 80, "model": ""}]
  }

```
- Day 1에는 `review`를 `null`로 둔다.
- `answer`는 0부터 시작하는 정답 번호. 정답 위치는 고르게 섞는다.
- 작성 후 `python3 -I tools/validate_lesson.py <파일>` (Offline_Translator 저장소)로 검증하고 통과해야 push한다.
